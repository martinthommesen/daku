# ServiceNow platform-health signals and the REST surfaces that expose them

Resolves issue #2 (part of #1). Question: for a platform owner watching **prod / test / dev**, which health signals exist, which REST surface exposes each, minimum role, and does it work on a Personal Developer Instance (PDI)?

Sources: ServiceNow product docs (Zurich bundle unless noted, `https://www.servicenow.com/docs/r/zurich/...`; the old `docs.servicenow.com/bundle/...` URLs 302 to this site) and `developer.servicenow.com`. Claims not backed by a doc page I could open are marked **[unverified]** — they are well-known platform behaviour but should be confirmed against a live instance before being built on.

## Ground rules that apply to every signal

| Fact | Source |
|---|---|
| Table API: `GET /api/now/table/{table}` with `sysparm_query`, `sysparm_fields`, `sysparm_limit`. "The calling user must have sufficient roles to access the data in the table" — i.e. normal table/field ACLs decide, there is no separate "REST" role for the Table API. Rows the user can't read are simply omitted; a table with no read ACL match returns 403. | [Table API](https://www.servicenow.com/docs/r/zurich/api-reference/rest-apis/c_TableAPI.html) |
| Aggregate API: `GET /api/now/stats/{table}?sysparm_count=true&sysparm_group_by=...&sysparm_avg_fields=...&sysparm_having=...`. Uses GlideAggregate, "only honors read-only queries if read access is defined for the table being called on based on role ownership". Counts without pulling rows — the workhorse for every "how many X since T" signal below. Relative-date filters use glide functions inside the encoded query, e.g. `sys_created_on>=javascript:gs.daysAgoStart(7)`, `sys_created_onONToday@javascript:gs.beginningOfToday()@javascript:gs.endOfToday()` (now-sdk `encoded-query-guide`). | [Aggregate API](https://www.servicenow.com/docs/r/zurich/api-reference/rest-apis/c_AggregateAPI.html) |
| Monitoring account: give it the specific read roles it needs plus `snc_read_only` (blocks insert/update/delete on every table regardless of other roles; also can't activate plugins or run SQL). Mark it non-interactive so its credentials only work for API calls, not the UI. | [Read-only role](https://www.servicenow.com/docs/r/zurich/platform-administration/user-administration/c_ReadOnlyRole.html), [Non-interactive sessions](https://www.servicenow.com/docs/r/zurich/platform-administration/user-administration/c_NonInteractiveSessions.html) |
| REST API Explorer (to discover endpoints) needs `web_service_admin`, `rest_api_explorer` or `admin`. Not needed at runtime. | [Access the REST API Explorer](https://www.servicenow.com/docs/r/zurich/api-reference/rest-api-explorer/t_GetStartedAccessExplorer.html) |
| Inbound REST rate-limit rules (`sys_rate_limit_rules`, per hour; 429 + `Retry-After`, `X-RateLimit-Limit/Reset/Rule` headers); counts/violations visible with `rate_limit_admin`. Poll gently. Table/Aggregate/Attachment/Import-Set API ACLs ship **deactivated**; if a customer activates them the monitoring user also needs `snc_platform_rest_api_access` [role name from community/KB]. | [Inbound REST API rate limiting](https://www.servicenow.com/docs/r/zurich/api-reference/rest-api-explorer/inbound-REST-API-rate-limiting.html), [Monitor rate limits](https://www.servicenow.com/docs/r/zurich/api-reference/rest-api-explorer/monitor-request-counts.html), [REST API overview](https://www.servicenow.com/docs/r/api-reference/rest-api-explorer/c_RESTAPI.html) |
| Diagnostic servlets `stats.do`, `threads.do`, `replication.do`, `thread_pool_stats.do` are HTML, not JSON. With `glide.security.diag_txns_acl=true` they are **admin-only** (or allow-listed IPs via `glide.custom.ip.authenticate.allow`); the Security Center page lists true as default/recommended, the system-properties reference lists false (any authenticated user) — check the instance. `xmlstats.do` returns the same node stats as XML **[behaviour unverified in docs; long-standing]**. | [Restrict performance monitoring access](https://www.servicenow.com/docs/r/zurich/platform-security/instance-security-hardening-settings/sc-performance-monitoring-acl.html), [Available system properties](https://www.servicenow.com/docs/r/platform-administration/r_AvailableSystemProperties.html) |
| PDI: "PDIs run all the same software as a paid ServiceNow instance", but are free, on low-performance hardware, not supported, hibernate when idle (wake takes 3–20 min via the developer portal), and are reclaimed after 10 days of no developer activity. Single admin user. Docs also state a PDI cannot be a clone source/target and cannot use MetricBase/IDR/ML, and many Store apps are not installable. Anything below that is plain Table/Aggregate API on OOTB tables therefore works on a PDI once it is awake. | [PDI FAQ](https://developer.servicenow.com/print_page.do?release=yokohama&category=now-platform&identifier=pdi_faq&module=guide), [Hibernation and Developer Instances](https://developer.servicenow.com/blog.do?p=%2Fpost%2Fhibernation-and-developer-instances%2F), [Understanding PDIs](https://www.servicenow.com/docs/r/application-development/understanding_pdis.html) |

## Signal by signal

Legend for **PDI**: yes = works out of the box; partial = works with caveats; no = feature/licence not available on a PDI.

Anything else (timeout, 5xx, hibernation splash HTML) = down/degraded. ## Recommended v1 signal set (≤6)

Chosen for: works on prod/test/dev **and** PDI, plain Table/Aggregate API, one read-only monitoring user with `admin` (or the minimal read ACLs) + `snc_read_only`.

1. **Up / latency** — `GET /api/now/table/sys_properties?sysparm_query=name=glide.war&sysparm_fields=value&sysparm_limit=1`; status + round-trip. Also yields **build version** for free (covers #8 drift with zero extra calls).
2. **Scheduled-job health** — `sys_trigger`: overdue Ready count, Error count (Aggregate API).
3. **Error-log rate** — `syslog` level=Error count/hour, grouped by source (Aggregate API, date-bounded).
4. **ECC/MID** — `ecc_agent` any status≠Up or validated≠true; `ecc_queue` output/ready backlog + error count.
5. **Outbound integration errors** — `sys_outbound_http_log` non-2xx count/hour + `sys_email` send-failed count.
6. **Drift** — `sys_plugins`/`sys_store_app` (id, version) diffed prod↔test↔dev; plus `clone_instance` last completed clone (prod only) to explain drift.

Skipped for v1: semaphores/`stats.do` (admin-only HTML scraping, single-node PDI is meaningless — add if Instance Observer isn't licensed and prod nodes matter), licensing (needs `usage_admin`, no PDI value), table growth (derivable later from stored Aggregate counts), sessions (nice-to-have), Instance Scan (batch, not a health poll — surface outstanding findings as a weekly report, not an alert), HLA/IO (licence-gated, off-instance).

## Open verifications before implementation

Run against a PDI with a `snc_read_only` user — `npx @servicenow/sdk query <table> -q '<encoded>' -f <fields> -o json` is a ready-made read-only Table API client for this (now-sdk `query-guide`); a 403/empty result per table answers the ACL question directly: (a) exact `syslog.level` choice values; (b) baseline read ACLs on `sys_properties`, `sys_trigger`, `syslog`, `ecc_agent`, `ecc_queue`, `sys_outbound_http_log`, `sys_plugins`, `sys_store_app`, `clone_instance`, `v_user_session` (expect admin on most — decide whether v1 simply requires an admin+`snc_read_only` account); (c) `xmlstats.do` XML shape; (d) whether `scan_result` is the results table name; (e) that `sysparm_query` with `javascript:gs.hoursAgoStart()` is accepted by the Aggregate API for a non-admin.
